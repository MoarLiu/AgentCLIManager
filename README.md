# Agent CLI Manager

一个原生 macOS App，用来管理装在机器上的各种 Agent CLI（Claude Code、Codex、Gemini CLI、opencode、aider…）：**发现装了哪些、每个工具都占了哪些文件、勾选后一次性移到废纸篓**，并且能把已经卸载但残留还在的目录找出来清掉。

做这个是因为：harness 越来越多，装的时候随手就来（npm、brew、厂商的 curl 脚本各一套），卸的时候要么忘了装过什么，要么找不到卸载命令，卸完还留一堆 `~/.xxx`、缓存和配置。

## 界面

左栏按性质分五组：

| 分组 | 含义 |
|---|---|
| **已安装** | 能在命令行里运行、且被识别为 Agent 工具的命令 |
| **仅残留** | 程序和 App 都不在了，只剩下文件 |
| **未识别** | 内容像 Agent 工具留下的，但找不到主人；默认全不勾选，交给你判断 |
| **其他 CLI** | 命令目录里的非 Agent 可执行文件 |
| **由桌面 App 使用** | 只作说明：这些位置被已装的桌面 App 占用，不在管理范围 |

右栏列出该工具的程序本体、启动链接、配置、数据、缓存、日志、登录凭据，每一条都显示大小、可勾选，并能打开「为什么这么判」看证据链。目录可以**展开一层**，用来「留着工具、只清里面的旧版本或备份」——比如 `~/.qoder/bin/qodercli` 里躺着的 167 MB 旧版本。

- 侧栏用工具徽标、右对齐大小和磁盘占用条快速定位大项；右栏把「入口 → 链路目标」分行展示。同名入口按扫描顺序列出，**不推断实际 shell 的 PATH 优先级**。
- 文件行默认只显示路径、简短归属、风险徽标和大小，完整判据通过「为什么这么判」查看；支持悬停/聚焦操作、右键复制路径、空格勾选和回车展开，路径始终可查看完整内容。
- 侧栏顶部可以在「工具」和「项目清理」之间切换，后者见下面的「项目清理」一节。
- 底部明确显示「将移走 X 项 · 大小」，并注明**清空废纸篓后才释放空间**。确认单把风险、将移走的条目和「不会动」的原因分开列出；结果页仅恢复本次批次，全局恢复栏可恢复全部未完成批次，即使扫描结果为空也保留入口。撤销失败会保留回执，保存错误与操作结果同时显示。丢弃恢复信息需要二次确认，条目仍留在废纸篓，但之后无法通过本 App 自动放回。浅色、深色外观都支持。

### 项目清理

侧栏顶部切到「项目清理」，添加一个普通文件夹（比如放项目的目录或「下载」），App 会在里面找闲置的开发依赖、
构建缓存和旧安装包。引擎和 `acm sweep` 是同一套，判定规则、护栏和回执见后面的「项目清理 `acm sweep`」。

- **文件夹要你自己添加**：家目录本身、系统目录、家目录的点条目和 `~/Library` 当场拒绝并说明原因。
  清单记在 `~/Library/Application Support/AgentCLIManager/sweep-folders.json`；「从清单中移除」只是不再列出，不动文件夹。
- 结果分「可清理 / 需复核 / 保留 / 跳过」四组，每一项写明原因。**只有「可清理」能勾选**，其余三组只读。
- **默认勾选**有依据的缓存、依赖和内容完全相同的重复安装包；标着「按文件名推测」的旧版本安装包不勾，要你自己点。
  重新扫描后沿用你原来的勾选。
- 「闲置 1 天以上 / 7 天以上 / 不看闲置时间」三档决定多久没写入才算可清理，默认 1 天。
- **「移到废纸篓…」和「永久删除…」都先打开确认单**：打开时对着磁盘把勾选的条目重新核对一遍，
  列出会动哪些、哪些勾了但不会动及原因。确认后只执行确认单上列出的那些；确认单开着时再改勾选不影响这一次。
  两种确认单都要先勾选核对项才能执行，永久删除的那一条写明「我已核对清单，并知道永久删除无法恢复」。
- 结果页分开列出已移走的、没有动的（附原因）和停在半路的（附现在所在的位置）。移到废纸篓的可以当场「放回原处」；
  侧栏底部的「可放回原处」列出历次清理中还没清空的内容，重新打开 App 后仍在。原位置已经有东西时不覆盖。
- 扫描结果放了超过 24 小时就不再执行，会先重新扫描。在这个页面按 ⌘R 只重新扫描当前文件夹。

## 归属判定：只认确定的证据

这是整个工具最要紧的部分。「这个目录是谁的、还算不算残留」按证据强度分三档，**只有「确定」才可能让条目被默认勾选**：

**算「确定」的只有三种**

1. 目录清单里写明的路径
2. bundle id 精确匹配（只查表，不从片段猜——`com.anysphere.sand` 其实是 Grok Bot，不是 Cursor）
3. 二进制链路包含关系：从 PATH 上的命令出发解析软链，程序所在的那个目录

**只算「推测」的**：名称相似、目录内容标记（`mcp.json`、`sessions/`、`ai-*.json`…）、代码签名、修改时间。它们只作为证据展示。

几条硬性保护：

- 被已装 App 的 bundle id 认领的路径**永远不进残留**（`~/.codex` 属于 ChatGPT.app，不能因为找不到 `codex` 命令就判成残留）；CLI 存在时也检查嵌套的 App 子目录
- 归属按**子路径**算：`~/.qoder/bin/qodercli` 是 CLI 独占，`~/.qoder` 整体与 Qoder.app 共用；跨组的 App 子项会阻止父目录整体移走
- 命令先按各自的产品/包身份分组；Volta、nvm、pipx、uv 等工具管理器目录不会把无关命令并入同一个卸载组
- `~/.local/share`、`~/.config`、`~/Documents` 这类位置的根目录**永远不可删**，只能清理通过护栏的具名子项；`.ssh`、`.aws` 等敏感目录及其内部条目全部受保护
- 家目录**顶层**目录除非清单声明独占，否则不默认勾选——几个 GB 都堆在这一层，判错代价太大
- 软链链尾必须是可执行普通文件；指向目录或不可执行文件的入口只报告异常，不会把目标当成程序本体
- 本 App 自身的数据目录拒绝任何操作

## 安全

- 卸载工具**只移到废纸篓**，从不 `rm`；可以「放回原处」。唯一会直接删除文件的是「项目清理」的永久删除：
  命令行要 `acm sweep apply --execute --permanent` 两个选项一起给出，界面要在确认单上勾选「我已核对清单，并知道永久删除无法恢复」。
  它只作用于判为「可清理」的缓存、依赖和安装包
- **永不 `sudo`**，需要管理员权限的条目只给出可复制的命令
- 默认勾选规则：已装工具的程序本体、启动链接、缓存、日志勾上；**配置和数据不勾**（会话历史、记忆都在里面），可用「选择全部」连同配置和数据一起勾选；登录凭据既不默认勾选也不参与全选。确定的旧残留可以默认勾选，但最近写入、共用、顶层未声明独占和归属不确定的条目不勾
- 执行前重新核对路径是否还在、进程是否在用；确认期间新启动的进程会拦住执行。按完整启动链安排程序、入口目录和链接的移动顺序，依赖必须已经成功；无法安全排序的循环依赖不执行
- 回执只记录恢复信息；放回前校验来源确实在废纸篓、目标仍通过路径护栏，并核对 inode（新回执）
- 撤销部分失败只移除成功项，失败回执保留在界面和本地账本中；不覆盖尚未放回的其他批次
- 确认单会单列「不会动」的条目及原因，并明确写出**移到废纸篓不会立刻释放空间**
- 本 App 不代改 shell 配置（只展示相关行），不调用包管理器，不运行安装脚本；终端包装脚本保留实际退出码

## 隐私

扫描结果、文件路径、登录凭据和撤销回执保留在本机。撤销账本位于
`~/Library/Application Support/AgentCLIManager/`，包含恢复所需的原路径和废纸篓路径。
分享截图、JSON 报告或回执前，请自行检查其中的路径、工具清单和账户信息。
点击打开文档、安装链接或在终端运行命令时，会使用对应的系统应用或上游服务。

## 构建与运行

```bash
./scripts/test.sh              # 单元测试（假家目录，不碰真实文件）
./scripts/test-cli.sh          # acm 端到端断言（假家目录，含卸载/放回往返）
./scripts/build-app.sh         # 构建并组装成 build/Agent CLI Manager.app
open "build/Agent CLI Manager.app"
```

工具链说明：

- **只编译引擎和 `acm` 命令行**：CommandLineTools 就够。
- **编译 SwiftUI 界面、跑单元测试**：需要 Xcode。macOS 27 SDK 里 `@State` 等是宏，宏插件（`SwiftUIMacros`、`TestingMacros`）只随 Xcode 提供。脚本会对单条命令设置 `DEVELOPER_DIR`，**不修改系统的 `xcode-select`**。

签名默认是 ad-hoc。想让系统授权在重新构建后依然有效，用固定身份：

```bash
CODESIGN_IDENTITY="你的签名身份名" ./scripts/build-app.sh
```

指定的签名身份签名失败时构建会终止。

### 发布验证与打包

```bash
./scripts/test.sh --no-parallel
./scripts/test-cli.sh
./scripts/build-app.sh
./scripts/package-dmg.sh
```

DMG 和 `SHA256SUMS` 输出到 `build/release/`。打包前自动扫描公开源码与 App，
检查个人绝对路径、本机账户名、常见密钥格式和意外混入的本地文件。
发布文件使用 `.gitignore` 排除构建缓存、开发历史、内部审查报告、截图及签名私钥。
公开前还需挂载 DMG，验证 App 签名、版本和启动行为。

当前版本为 0.3.1（build 6），要求 macOS 14 或更新版本。当前安装包为 arm64，
采用 ad-hoc 签名，尚未进行 Apple 公证，首次打开可能受到 Gatekeeper 拦截。

界面调整时可以用截图模式检查，它不会动任何文件：

```bash
"build/Agent CLI Manager.app/Contents/MacOS/AgentCLIManager" \
  --snapshot /tmp/acm.png --select "Qoder CLI" --sheet confirm \
  --appearance dark --size 920x580

# 项目清理：只读扫描一个文件夹并截图
"build/Agent CLI Manager.app/Contents/MacOS/AgentCLIManager" \
  --snapshot /tmp/sweep.png --sweep ~/Projects --sweep-idle 0 --sheet sweep-confirm
```

`--sweep <文件夹>` 直接切到「项目清理」并扫描这个文件夹（不读写文件夹清单）；`--sweep-idle 24|168|0` 选闲置档位；
`--select-all` 连旧版本安装包一起勾上；`--sheet` 可取 `sweep-confirm`、`sweep-permanent`、`sweep-result`、
`sweep-result-permanent`、`sweep-recovery`；`--demo pending` 摆一批假的「可放回原处」，`--demo residue` 从磁盘列出实际的
永久删除暂存，`--demo restore-failed` 摆一条放回失败。截图模式下执行和放回都被禁用，结果页和可放回内容是内存里的示意数据。

## 命令行 `acm`

只读扫描、演练和卸载/放回操作：

```bash
swift build --product acm
./.build/debug/acm scan --sizes          # 扫描并列出大小
./.build/debug/acm scan --json           # 机器可读
./.build/debug/acm scan --verbose        # 带上判定证据
./.build/debug/acm plan "Qoder CLI"      # 只演练，打印卸载计划
./.build/debug/acm plan "Qoder CLI" --execute --receipts /tmp/r.json
./.build/debug/acm undo --receipts /tmp/r.json
```

`plan` 默认只演练，加 `--execute` 才会真的移到废纸篓；`--receipts` 保存回执，`undo` 放回并保留失败项供重试。目标按 id/精确名字/子串匹配，子串有歧义会退出而不会替你选。`--all` 排除单独的登录凭据，父目录覆盖凭据时仍会提示风险。

- 所有选项在扫描前校验；`--home` 缺值、未知选项、重复选项和未知子命令退出码为 2，不会退回真实家目录
- 退出码：0 完全成功，1 运行时失败，2 用法错误；`catalog --json` 输出可解析的完整清单
- 新执行的 `--receipts` 必须使用**尚不存在的路径**（支持 `r.json` 这样的相对文件名）；已有回执、空数组文件、目录和软链一律不覆盖。目标确定且计划非空后，会排他创建实际回执文件，确认可写后才移动工具
- 新回执通过预留的文件描述符写入并同步，不做原子替换；保存失败会返回非零状态并输出完整恢复 JSON，供手工保存。中止可能留下 `[]`，不能仅凭预留文件判断执行成功；之后新执行需另选文件名。`undo` 更新剩余回执仍采用原子写
- `test-cli.sh` 在 `mktemp` 假家目录中验证真实废纸篓往返及保存失败后的恢复，只使用测试自建文件，结束后检查无遗留

### 项目清理 `acm sweep`

在你指定的目录里找闲置的开发依赖、构建缓存和旧安装包。它和上面的工具管理范围互补：
那边只管家目录的点条目和 `~/Library`，这边只管普通文件夹，所以有一套自己的护栏。
`scan`、`items`、`inspect` 只读；`apply` 和 `restore` 默认只预演，带 `--execute` 才动手。
图形界面的「项目清理」用的是同一套引擎和同一个回执目录，所以界面里清理的可以用 `acm sweep restore` 放回，反过来也一样。

```bash
./.build/debug/acm sweep scan ~/Downloads                      # 只读扫描
./.build/debug/acm sweep scan ~/Downloads --out /tmp/plan.json # 同时把计划另存为新文件
./.build/debug/acm sweep items /tmp/plan.json --status cleanup # 分页查看，取得稳定 ID
./.build/debug/acm sweep inspect /tmp/plan.json ITEM_ID        # 识别依据、文件身份、保留的版本
./.build/debug/acm sweep apply /tmp/plan.json                  # 预演：重新核对，列出会动哪些
./.build/debug/acm sweep apply /tmp/plan.json --execute        # 移到废纸篓，打印回执路径
./.build/debug/acm sweep restore <回执> --execute              # 按回执放回原处
./.build/debug/acm sweep apply /tmp/plan.json --execute --permanent   # 直接删除，不可恢复
```

每个候选项得到四种结论之一：

| 结论 | 含义 |
|---|---|
| `cleanup` | 有生成依据、闲置够久、没有进程占用 |
| `keep` | 该产品、架构和格式下最新的安装包 |
| `review` | 证据不够，或最近仍有写入，交给你判断 |
| `blocked` | 有保护条件拦着 |

- **名字像不算数**：SwiftPM 缓存要有工作区状态文件，`node_modules` 要有 npm 或 pnpm 的安装标记和项目清单，
  `__pycache__` 里只能有字节码，`.next`、`.turbo` 要有对应的配置文件。`build`、`dist`、`.cache`
  不会仅凭名字成为候选项；名字像缓存而没有依据的只列为 `review`。
- **安装包**按所属项目、产品、CPU 架构和格式分组，保留最新稳定版和比它更新的预览版。同版本的重复件只有
  SHA-256 相同才去重，内容不同的都保留。应用包按 `Info.plist` 的身份和版本识别；普通 ZIP 只有顶层恰好装着一个
  App 时才算安装包。版本号取自文件名，所以「已有更新版本」是推测：`apply` 不会顺带清理这一类，
  要用 `--id` 点名或加 `--include-old-versions`；内容完全相同的重复件是确定的，照常清理。
- **受保护的**：Git 已跟踪的文件、缓存里的独立 Git 仓库、符号链接、其他用户或其他卷上的内容、
  有进程打开着的目录、工作目录在所属项目里的开发工具、本 App 自身的文件，以及
  `Sources`、`docs`、`design`、`data`、`backup`、`.ssh` 等目录的内部。Git 或进程表问不出结果时一律按受保护处理。
- **扫描根必须明确给出**：家目录本身、家目录的上级、卷的根、系统目录都不接受；家目录的点条目和
  `~/Library` 归工具管理部分，同样不接受。带 `--home` 演练时，扫描目录必须在假家目录之内。
- 默认要求闲置 24 小时，`--idle-hours 0` 表示不看闲置时间；`--exclude` 可以给多次，
  候选目录里含有被排除的路径时整个跳过；`--max-entries` 限制单个候选目录的条目数。
- 占用按文件分配块估算，硬链接只算一次；APFS 克隆和其他进程的写入会让实际释放量不同。
- `--json` 时 stdout 只有一个 JSON 对象，成功为 `{"ok": true, "schema_version": 1, "data": …}`，
  失败为 `{"ok": false, "schema_version": 1, "error": {"code", "message", "details"}}`。
  退出码沿用 `acm` 的约定：0 成功，1 运行时失败（计划损坏、找不到项目），2 用法错误（扫描根不被接受、
  选项有误、计划文件已存在）。
- 计划文件带内容摘要，改过或损坏的计划不认；`--out` 只创建新文件，已有同名文件（包括软链）时拒绝。
  摘要防的是误改和损坏，不是防伪。

执行（`apply`）和放回（`restore`）：

- **计划只是当时看到的样子**。`apply` 先重新扫描一遍，逐项核对：计划不超过 24 小时、扫描根没被换掉、
  条目仍判为 `cleanup`、整棵目录树的指纹和计划里一致、赖以清理的那份保留安装包原样还在。
  移动每一项之前再核对一次指纹、Git 跟踪和进程占用。任何一条对不上，这一项标为「已跳过」并说明原因，退出码 1。
- **默认移到废纸篓**：条目进入 `~/.Trash/ACM-Sweep-<执行编号>/`，在访达的废纸篓里看得到；
  清空废纸篓之后空间才会释放。废纸篓和扫描目录不在同一个卷上时拒绝执行（不会跨卷复制）。
- **`--permanent` 直接删除，不可恢复**：先移进扫描根里的 `.acm-sweep-staging/`，核对无误后再删。
  删除全程不跟随符号链接——缓存里的软链只删链接本身，指向的东西不动。
- **移动不覆盖**：用「目标位置没有东西才移」的原子改名；移动之后再核对一次指纹。
  移动后核对失败时，内容留在暂存位置，结果里给出路径（`recovery_path`），后面的条目不再继续。
  永久删除中途失败时，只保留尚未删除的部分；已经删掉的内容不可恢复。
- **回执**：每次执行在 `~/Library/Application Support/AgentCLIManager/sweep/runs/` 里留一个 JSONL 回执，
  移动前先落盘，回执不会自动清理。`restore` 按它把还在暂存位置的内容放回原处：原位置已经有东西时不覆盖，
  暂存内容被改过时不放回，已经永久删除的放不回来。回执被当作不可信输入——
  放回的来源只能是那次执行自己的暂存目录，去向只能是原来的相对路径。
- 同一个扫描目录同时只允许一个 `apply` 或 `restore`。带 `--home` 演练时，废纸篓、回执和执行锁全在假家目录里，
  计划和回执指向的目录也必须在假家目录之内。
- `--json` 时，有条目被跳过或没走完的结果是 `{"ok": false, …, "data": {逐项结果}, "error": {"code": "incomplete_operation", …}}`。
- 已知限制：永久删除遇到自己删不掉的内容（例如没有写权限的子目录）会停下，剩余部分留在暂存目录里等你处理；
  SwiftPM 缓存里如果有依赖的 Git 检出（`.build/checkouts`），整个缓存按「含独立 Git 仓库」跳过。

这部分移植自独立的 BuildSweep 命令行，候选项、结论、原因和指纹与它逐项一致，
`./scripts/test-sweep-parity.py` 在同一棵临时目录树上对拍两者（找不到 BuildSweep 时跳过）。
有意不同的地方：不接受家目录的点条目和 `~/Library` 作为扫描根；保护的是本 App 自身的文件；
退出码按 `acm` 的约定；两边的计划文件和回执互不通用；`apply` 默认不清理「已有更新版本」的安装包。进程占用通过系统自带的 `lsof` 查询，
它报告任何不完整时所有候选项都不会判成 `cleanup`。

## 目录清单

`catalog/*.json` 是识别依据，构建时合并进二进制。每条产品写：命令名、bundle id、团队 ID、各类路径（是否共用、是否独占）、各渠道安装命令。

- 内置条目只写**对照官方文档或本机实测核实过**的字段，没核实的宁可不写。
- 自己补充新工具不用重新编译：写
  `~/Library/Application Support/AgentCLIManager/catalog.json`，格式相同，id 不与内置重复即可。

改完清单后跑 `./scripts/embed-catalog.sh` 重新嵌入。

工具标识放在 `assets/tool-logos/`，文件名与产品 `id` 一致；官方来源与授权主体见该目录下的 README。
CLI 图标打进 app bundle，**运行时不联网取图**；没有对应文件的用首字母兜底。
桌面 App 不维护一份独立 logo 清单：扫描已经给出 `.app` 路径，直接通过 `NSWorkspace.icon(forFile:)`
读取 App 自己的图标（包括 `CFBundleIconFile`、`Assets.car` 与新版 `.icon`），并优先于同厂商 CLI 图标；
读不到时才按精确 bundle id 匹配 CLI 内置图或回首字母，不按名称猜。
更新图标跑 `./scripts/fetch-tool-logos.sh`（可只指定某几个 id），再重新 `./scripts/build-app.sh`。

## 已知限制

- **不扫 `~/Library/Containers` 和 `Group Containers`**：首次访问会触发系统授权弹窗，留给后续版本做成用户主动点「加载」。
- **家目录里只处理点条目和 `~/Library` 的几个类别**：`~/bin/foo`、`~/go/bin/foo` 这类放在普通目录里的独立二进制能被识别和列出，但标为「不可删除」，需要自己动手删。这是路径护栏有意的保守范围。
- **不代改 shell 配置**：只列出 rc 文件里相关的行，卸载后请自己删掉。
- **安装只给命令**：从目录清单挑工具，命令可以复制，也可以点「运行」——那会打开「终端」，在你自己的 shell 里原样执行这条命令。命令来自内置清单或你自己的 `~/Library/Application Support/AgentCLIManager/catalog.json`；本 App 不校验命令内容，也不在自己的进程里执行。
- **时间戳只看目录自身和第一层子项**：更深的写入反映不出来，所以「最近没写入」只是推测，不是证明。
- **大小以 `du -skx` 为准**；有读不到的子目录时显示「≥ X」并标为未量全，不计入可释放总量。硬链接与 APFS 克隆的跨条目去重没有做。
- **桌面 App 本身不卸载**，只识别它，以免把它在用的目录误判成残留。
- **启动脚本只做保守静态检查**：仅对能完整识别的直接 `exec` 语句判断目标是否全部缺失；含动态目标、分支、函数或 here-document 的复杂脚本，不据此认定为损坏或残留。
